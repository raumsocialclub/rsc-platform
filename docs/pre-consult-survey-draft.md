# 상담 전 고객 정보 설문 (/apply) — 초안 (2026-11-03)

광고 랜딩 링크 또는 직접 전달 URL 로 쓰는 「상담 전 설문」. 레퍼런스(결혼정보회사 웹 설문 녹화 영상, 2026-10-06)의 문항을 **그대로** 옮겨 `/apply` 에 구현했다(2026-11-03, 요청: 라움용 축약 없이 레퍼런스 토대로).

## 구현 (2026-11-03)

> 2026-11-04 구조 변경: /apply 는 공개 페이지가 아니라 **관리자가 발급한 비밀 링크(/apply/<토큰>)로만 열리는 설문**이다. 전화 상담 완료 → 니즈가 확실한 분에게 어드민 「상담 전 설문」에서 링크 발급·전달 → 1회 제출 → 상담 신청에 「설문」으로 수집. 일반 설정의 온오프 토글·?ref=·UTM·메타 픽셀 Lead 이벤트는 뺐다(광고 랜딩이 아니므로). 홈 상담 신청(/fit-check)은 메타 광고용으로 그대로.
>
> 2026-11-04 추가: 어드민 「상담 신청」에 종류 필터(전체 / 상담 전 설문(/apply) / 홈 상담 신청)가 생겼고, 설문만 고르면 목록의 「성향 결과」 자리에 성별·출생연도가 보이며
> 주관리자는 「설문 응답 CSV」(설문 전 문항이 열, 한 응답이 한 줄)로 내려받아 분석할 수 있다. /api/apply 는 같은 IP 10분 5회 제한 + 링크 토큰 필수.
- 주소: `/apply` · 광고는 `/apply?utm_source=…&utm_campaign=…`, 직접 전달·추천인은 `/apply?ref=코드`(추천인 코드 칸에 자동 입력). 검색엔진에는 노출하지 않는다(noindex).
- **온오프**: 어드민 → 일반 설정 → 「상담 신청 · 광고 측정」 → **「상담 전 설문(/apply) 열기」**. 끄면 방문자에게 「닫힘 안내 문구」만 보이고 API 도 거부한다. 관리자가 로그인한 상태면 꺼져 있어도 미리보기로 설문이 보인다. 기본값은 꺼짐.
- 문항 정의: `lib/apply/schema.ts` (아래 1절 표와 1:1). 화면 `components/apply/ApplyForm.tsx`, 저장 `app/api/apply/route.ts`.
- 8단계 · 「이전/다음」 · 마지막 단계에 개인정보 동의 + 「완료」. 필수는 기본 정보의 이름·성별·생년월일·휴대폰뿐, 나머지는 비워도 된다. 작성 중인 답은 브라우저(sessionStorage)에만 임시 저장.
- 저장: 기존 `inquiries` 테이블. 이름·휴대폰·이메일은 컬럼, 나머지는 `answers.answers[]`(어드민 상세가 그대로 표시) + `answers.apply`(원본 키-값). `answers.form = "apply"` 로 구분하고 어드민 「상담 신청」 목록에 「설문」 배지가 붙는다. 보관 180일 자동 삭제·CRM 시트 연동(전화번호)·UTM 필터·CSV 는 기존 그대로.
- 레퍼런스에서 바꾼 것: 가입 경로 선택지의 타사 고유 항목(특정 유튜버·책 이름)은 빼고 인터넷 검색/지인 추천/유튜브/SNS 광고/인스타그램/기타로 두었다. 시/군/구는 드롭다운 대신 직접 입력. 그 외 문항·선택지·안내 문구(키 작성 경고, 노후 준비 기준, 연애성향 안내)는 영상 그대로.
- **열기 전에 확인할 것**: 개인정보처리방침의 수집 항목(현재는 이름·휴대폰 중심)에 학력·직업·소득·자산·가족관계·이상형 조건 등을 추가해야 한다(동의 문구에는 이미 적혀 있음). 「거짓된 키 작성 시 환불 없이 영구 이용 제한」 문구는 레퍼런스 회사의 정책이므로 라움 정책과 맞는지 검토.

## 2. (참고 · 미적용) 라움소셜클럽에 맞게 바꾼 원칙

1. **목적이 다르다.** 결정사는 「조건 매칭」, 라움은 「어떤 사람과 어떤 경험을 원하는지」 파악해 상담과 프로그램 추천에 쓴다. 그래서 자산·부모 재산·가족사·차량은 **빼고**, 라이프스타일·관심 활동·관계 기대치 문항을 **넣는다**.
2. **광고 랜딩은 짧아야 한다.** 목표 소요 시간 3~4분, 한 화면 1~3문항, 총 5단계 ≈ 25문항. 레퍼런스의 90개 문항을 그대로 쓰면 이탈이 크다.
3. **개인정보 최소화.** 상담 연락에 꼭 필요한 것(이름·휴대폰·나이대·거주 권역)만 필수. 학교명·회사명·연봉·자산·가족 정보는 받지 않는다(개인정보처리방침 제4조 보관 180일 원칙 유지). 민감정보(종교·건강)는 받지 않는다.
4. **기존 자산 재사용.** 이미 있는 `/fit-check`(성향 6문항 → 3유형 결과)와 상담 신청(inquiries) · 어드민 「상담 신청」 · CRM 시트 연동을 그대로 쓰고, 이 설문은 그 **앞단(랜딩)** 으로 붙인다. 결과 화면에서 성향 유형을 보여 주면 응답 동기가 생긴다.
5. **콜 현황 인터뷰 태그와 맞춘다.** 어드민 「인터뷰 니즈 분석」 주제(원하는 것 · 관심 활동 · 가능한 일정 · 결정사 경험 · 금액 반응 · 프로필 · 후속 요청)와 같은 축으로 문항을 설계해, 설문 답변과 콜 메모가 같은 표로 집계되게 한다.

## 4. 저장 · 어드민 연동(안)
- 저장: 기존 `inquiries` 테이블에 **그대로** 저장(name · phone · email · answers jsonb · utm · status). `answers` 에 STEP 2~5 응답과 결과 유형을 넣는다. 새 테이블 없음.
- 어드민: 「상담 신청」 상세 패널에 설문 답변이 이미 표시되므로(`answers.answers[]`) 새 화면 없이 보인다. CSV 내려받기에도 포함 가능.
- 콜 현황: 전화번호로 CRM관리 시트와 이미 연동되므로, 설문 응답 ↔ 콜 결과가 자동으로 한 사람으로 묶인다.
- 유입 광고: 랜딩 URL 의 UTM 을 `utm` 에 저장(기존 로직) → 어드민 유입 필터·CSV 그대로 사용.
- 보관: 180일 자동 삭제(기존 크론) 유지. 학교명·회사명·자산 등은 애초에 받지 않으므로 추가 정책 변경 없음.

## 5. (해결됨) 검토 요청 — `/apply` 신규 · 레퍼런스 그대로 구현
1. **URL**: `/apply` 로 할지, 기존 `/fit-check` 를 이 설문으로 **교체**할지. (교체하면 링크 하나로 통일되지만 지금의 6문항 설문은 사라짐)
2. **STEP 2 범위**: 하는 일 · 학력 · 키 · 음주 · MBTI 중 **빼고 싶은 것**이 있는지. 광고 유입 이탈을 줄이려면 STEP 2 전체를 「선택」으로 두는 것을 권장.
3. **STEP 4 성향 문항**: 6개로 줄인 것이 괜찮은지, 레퍼런스처럼 더 넣을지.
4. **마케팅 수신 동의**(문자·카카오 안내) 체크를 넣을지.
5. **직접 전달 URL**: 상담사가 개별로 보낼 때 `?ref=상담사코드` 를 붙이는 방식이면 되는지(어드민 「유입 광고」 필터에 상담사별로 잡힘).
