## 2. 변경 요약

- `lib/legal/content.ts`: 이용약관 20개 조 + 부칙·개정 이력(멤버십 전면 개정), 개인정보처리방침 17개 조 + 부칙·개정 이력(멤버십 운영 14~21호 신설, 채널톡·Google 수탁, 자동화된 결정 없음·유출 통지 신설), 환불규정(리드 모드 숨김 페이지)도 약관 제15조와 같은 기준으로 교체. `PRIVACY_CONSENT_VERSION` 2026-11-27, `LEGAL_UPDATED` 2026년 11월 27일. 상담 신청 동의 범위(이름·휴대폰·직업·학력·거주지·180일)는 변동 없음.
- `lib/cms/schema.ts`: 약관 문서 기본 「시행일」을 `LEGAL_UPDATED` 로(그동안 /terms 는 DB 저장본이 없어 「2026년 10월 1일」로 보였음), 설명 보강.
- `tests/legal.test.ts`(6): 날짜·버전, 1:1 매칭 0건, 핵심 조항, 실제 처리 반영, 조 번호 연속성과 내부 참조, CMS 기본값. 총 294 통과.
- 어드민 영향 없음. DB·고객 데이터 변경 없음(아래 4절의 배포 절차에서만 `legal.privacy` 저장본 교체).

## 3. 운영자 결정 필요 (배포 전 확인)

1. **환불 기준(약관 제15조)** — 가입비: 납부 7일 이내·미이용 시 전액 / 이후 중도 해지 시 잔여 기간 일할 환불 − 위약금 10%(방문판매법 계속거래·소비자분쟁해결기준 수준) / 행사 참가비: 3일 전 전액 · 2일 전~전날 50% · 당일 불가. 다른 기준을 원하면 숫자만 바꾸면 됨(약관 제15조 + 환불규정).
2. **심사 서류** — 「열람·확인만 하고 사본·사진을 보관하지 않는다」로 썼음. 실제로 사본을 보관할 계획이면 보관 항목·기간을 정해야 하고 방침 제2조 14호·제4조 5호·제11조를 바꿔야 함.
3. **멤버 정보 보유 기간** — 멤버십 종료 후 1년(분쟁·재가입 이력), 미승인 신청자 심사 기록 6개월, 동반 지인 연락처 행사 후 30일. 가입 승인된 신청자의 사전등록 정보는 180일 자동 삭제 대상에서 「멤버 정보로 옮긴다」고 썼는데, **현재 코드는 승인 여부와 무관하게 180일 뒤 삭제**함 → 멤버 관리 화면/DB(승인 회원 보존)를 만들기 전까지는 운영진이 승인 회원 정보를 별도로 관리해야 함(후속 작업 후보).
4. **상담 콜 시트** — 시트의 상담 기록도 180일 기준으로 정리한다고 썼음(수동). 시트 공유 범위를 운영진 계정으로 제한하고, 180일 지난 행 삭제 주기를 정할 것.
5. **채널톡 대화 보관** — 「문의 처리 완료 후 1년」 기준으로 채널톡 설정의 보관 기간을 맞출 것(채널톡 데스크 설정). 채널코퍼레이션의 처리 위치는 채널톡 방침을 참고하라고 적었음 — 법률 검토 때 국외 이전 해당 여부 확인.
6. **상담 전 설문(/apply)** — 1:1 매칭용 문항(이상형 조건·연애 성향 등)이 남아 있어 방침에는 「운영하는 경우에 한함」으로 짧게만 남김. 소셜클럽 운영에서 안 쓰면 어드민 링크 발급을 중단하거나 문항을 정리하는 것이 깔끔함.
7. **Meta 리드 광고** — 상담 콜 시트에 「메타 CSV」가 누적된다고 되어 있어 수집 방법에 「Meta 리드 광고 양식으로 신청한 경우」를 넣었음. 리드 광고를 쓰지 않으면 제3조 2호 삭제.
8. **혼인 상태 변동 신고(약관 제13조 2항)** — 회원 자격 기간 중 혼인하면 멤버십 종료·일할 환불. 유지할지 확인.
9. **공고·시행일** — 둘 다 2026년 11월 27일(상담 신청자에게 불리한 변경이 없고 멤버십은 아직 성립 전이라 같은 날 시행). 7일 사전 공지를 원하면 날짜만 바꾸면 됨(`LEGAL_UPDATED`·부칙·개정 이력·`PRIVACY_CONSENT_VERSION`).
10. **법률 검토** — 가입비 환불 공식, 계속거래 해당 여부, 제휴 혜택 제3자 제공 동의 방식, 행사 사진 동의 방식은 변호사 검토 권장.

## 4. 배포 절차 (사용자 「배포해」 지시 후)

1. 운영 배포(브랜치 → production) — 코드 기본값은 `/terms`·`/refund` 에 바로 적용.
2. `/privacy` 는 운영 DB `site_content` 의 `legal.privacy` 저장본(11-20 버전, md5 e2059e2e…)이 우선하므로, 배포 직후 저장본을 새 기본값으로 교체(이전본은 `site_content_history` 자동 보관). 방법: 어드민 → 사이트 관리 → 약관 → 개인정보처리방침 → 「기본값 복원」, 또는 SQL 로 `data.sections`·`data.updated` 교체.
3. 운영 주소에서 `/terms` `/privacy` 200, 「1:1 매칭」 0건, 부칙 2026년 11월 27일, 채널톡·Google 문구 표시 확인.
4. 스테이징은 운영 DB 를 공유하므로 배포 전에는 `/terms` 만 새 문구, `/privacy` 는 옛 저장본이 보인다.
